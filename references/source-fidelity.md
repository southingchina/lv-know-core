# 来源忠实性与两层配对验收

适用于二层提炼、由二层生成三层及已有内容修订。沿用同一流水线、来源身份、
去重次序与写入授权，不另建知识库。策略标识：`source-fidelity-v1`。

## 提炼时检查什么

从权威来源元数据与完整原稿提炼；不要把原卡标题、分析、旧知识点和建议作为作者原话。
每个命题明确对象、动作/判断、条件、程度、时间及证据性质。原稿确有支持才写入；
额外建议应标为助手推论或移出来源知识命题。

- **程度与范围**：保留“可能、往往、比较、目前、作者认为/体验/预测”。
  单个产品/两张示例不自动扩大为产品类别、长期能力或跨人群通用效果。
- **结果**：同时读演示后的反馈。要求AI做某事不代表它做成了；不满意、失败、
  返工与版本条件不能在提炼中消失。
- **边界也需依据**：在Mac演示不推出仅限Mac；原稿未谈专业流程不推出专业流程不适用。
  可写“原稿未说明/本次未核验”，不要补成排他规则。
- **数字和类别**：不把技能总数当行业技能数，不把跑分接近当成同任务效果接近。
  未核实的营销数量、性能和效果数字按语义规则删除或留待核；方法仍成立时保留有来源的
  方向性表达。步骤编号和作者建议的参数不能伪装成效果统计。
- **ASR**：原始写法保留。校名须有原画面、官方名或明确上下文依据；“Kimi看着像错词”
  不是核名依据。无法可靠辨认的名字标待核，不凭相似发音补齐。
- **证据类型**：来源观点、作者自述、建议、预测与独立验证事实分别表述。
  文字稿没有附件，不证明视频画面没有展示；二层文档可回源，也不表示已看过失效的外链。

## 原视频不可用时的上下文恢复

视频删除或无法回看时，继续利用完整转写、前后文、重复叫法、功能组合与已有明确名称
恢复可用内容，不把回看视频作为完成文字提炼的必要条件。用户已要求结合上下文推定时，
直接执行此路线；不要反复要求用户找回视频。

- 原始ASR和逐字引文不改。规范名称、释义和重建的开场另栏，标明“上下文推定”或
  “开场释义，非逐字原话”，记录对应原始词形和判断依据；推定不冒充听过原音。
- 多个线索一致时统一术语，例如SOLO模式与AI编程工具可辅助辨认TRAE，Google生态的
  自定义助手与重复近音可辅助辨认Gems。官方资料可校正拼写和功能指代，不能倒推原视频
  一定说过什么，也不能用当前版本替换作者当时的体验。
- 名称不能唯一恢复、但方法不依赖名称时，用功能性称呼保留方法；不必因此挂起整条知识。
  无法恢复的作品/账号名不强猜身份。只有缺失信息会改变方法、方向、合并或风险时才待核。
- 视觉钩子可根据转写登记其演示对象、对比结构和作者承诺，无需认证画面效果。
  普通导语如实记录；只有片段时写“片段起句”，不冒充完整视频开场。效果和数量明确归于
  作者自述，缺少证据的保证删除或收窄，不把“未独立核验”本身当成流程阻塞。
- 可以通过收窄、归因、分列实现和上下文恢复解决的项，应产出修订正文并关闭原待核项，
  不仅给出修改建议。来源覆盖/引用缺失另行记账，不混同为内容无法理解。

## 多来源与身份

先按知识点的主来源查主引文，再核其他来源支持的共同命题和各自条件。引文不在抽样的
副来源中不必然是串引文；不能跳过主来源就判错。插件工作台与任意白板网站可能共享
上层方法，但具体步骤或依赖不同，须分列实现、拆点或留灰区，不把某一实现的限制
强加给全部来源。

卡ID、来源库名和文件路径按真实值逐字保留，禁止用正文空白清理压缩连续空格。
非法换行拒绝并回查来源，不静默改成另一个ID/路径。文件改名、迁移须维护旧ID映射，
验证实体路径和块锚点；未知公共作品ID不能由文件哈希冒充。

修订钩子正文时同步审计元数据，旧的`no_hook`、强度分和旧子卡引用不可继续作为当前结论。
旧值保留在分析归档；文字支持用`text_supported`，尚待画面、音频或边界判断用
`pending_review`，非口播来源用`not_applicable`，并以`hook_review_scope`标清核验范围。
文字引文有来源不表示已核验画面或效果。样本副本设`preview_only: true`，旧`layer: material`
与缺失的来源类型按已核实的来源类别规范后，再用真实SourceMaster解析器验收。

## 用户要求先抽样时

锁定约定样本的ID、路径、原稿哈希和抽样序号，后续重做复用这一批。
追踪每张样本贡献的全部知识点，主来源不在样本内时也回读该主来源。
没有贡献的样本分别记录零贡献理由、待审候选、已知合并去向或原因未明，不能计为通过。
输出逐卡对照与逐知识点的修前/修后记录。

样本实际语义复核命题、引文和边界。全量阶段沿用结构化指纹与确定性处理→结构排除→
向量近邻→模型只审灰区；不另做全量两两比较或重复全量模型审核。已有判断只在来源
原稿及知识点完整版本未变时复用。语义生成、生成时自检、额外样本审核和独立事实核验
分别计数，不能将读取文件计为模型审核。

## 内容检查记录和发布检查

所有活跃预览知识点必须有实际检查记录，至少核对上述来源支持关系；待修与灰区
留在候选/待审表，不能混入拟发布版本。格式如下：

```json
{
  "policy": "source-fidelity-v1",
  "comparison_sha256": "本次run-state中的comparison.sha256",
  "preview_path": "本次layer3-cache/preview/atoms.jsonl的绝对路径",
  "preview_sha256": "上述文件的SHA256",
  "reviews": [
    {
      "atom_id": "对应真实atom_id",
      "content_hash": "对应当前atom.content_hash",
      "verdict": "supported",
      "method": "semantic_sample",
      "reason": "具体判断依据，不能只写引文匹配或哈希一致"
    }
  ]
}
```

`method` 使用 `source_only_extraction`（本次原稿提炼时实际自检）、`semantic_sample`
（实际样本复核）、`semantic_gray`（灰区复核）、`unchanged_review_reuse`（完全未变版本
复用）之一。引文匹配器本身不能签发这些方法。记录可以另外包含已排除的待审行，
但每个活跃ID只能有一个匹配当前内容哈希的`supported`结论。

先执行`stage_gate.py record-content-review --state <state> --review <receipt>`，
再执行既有`check-layer3-publish`。程序只验证覆盖、版本和文件未变，不会自动判断自然
语言真假；调用者仍须实际检查。重新比较会撤销放行记录，修改预览或审核文件会使旧
记录失效。旧运行须补核，兼容命令`check-commit`不绕过检查。

检查通过只表示当前预览满足此范围的内容与版本条件，不代表获得正式写入授权，
也不代表所有外部事实已独立验证。正式发布继续遵守精确目标、单写者、备份和回读。
