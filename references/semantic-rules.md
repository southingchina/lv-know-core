# 三层语义规则

## 拆点

- 一条候选只表达一个判断、方法、关系或风险。
- 完整原始ASR或来源正文是语义依据；已有提炼区、标题和分析不能充当原话证据。
  校对稿只在改动有核实依据且可与原稿对照时辅助理解，不覆盖原稿或绕开原句定位。
- 案例若只用于说明观点，不自动升级为普遍规律。
- 转录错词只有在上下文明显时修正，不补造事实。

命题、边界及多来源合并按 [来源忠实性规则](source-fidelity.md) 检查。引文存在
只证明出处，不证明由它概括出的程度、适用范围、效果或限制成立。

## 三类分流

| 条件 | 状态 |
|---|---|
| 命题清晰、来源可回溯，直接或安全弱化后仍成立 | `进入三层` |
| 是否合并、边界、方向或风险暂时无法可靠判断 | `待人工判断` |
| 删除风险信息后无法形成独立稳定观点 | `仅保留二层` |

待判断和仅保留二层必须填写原因，不阻塞其他合格候选。

## 数字和绝对化表达

- 未核实具体数字不写入三层正文。
- 原话明确支持方向时，删除数字并保留方向性作者观点。
- 原话只报告孤立数字、无法支持趋势时，仅保留二层。
- 绝对因果改为条件性或方向性关系，不能保留效果保证。
- 法律流程、平台内部机制和固定效果缺少依据时，不补造验证结论。

研究报告数字可以保留，但必须同时记录数据版本、分母和样本范围。报告写明的样本份额不得改写为市场份额；观察性或相关性发现不得改写为因果结论。研究报告作为独立证据类型，不参与“两个以上独立博主”的多人共识计数。

## 问题索引

- 问题键描述“这个观点回答什么问题”，不是宽泛主题名。
- 优先复用注册表中的键和别名。
- 只有共享问题键或被语义兜底召回的点才进入比较。
- 索引只负责召回候选；合并仍比较对象、方向、条件、用途、证据和边界。

## 关系判断

| 关系 | 处理 |
|---|---|
| 无等价旧点 | 新建 atom |
| 同问题、同对象、同方向、同条件和边界 | 合并并保留全部来源 |
| 同一博主重复 | 合并来源，不升级多人共识 |
| 两个以上独立博主真同义 | 合并并标记多人共识 |
| 同一问题、方向相反 | 双方分别标记争议观点 |
| 已形成明确对立 | 增加中立争议总览并关联双方 |
| 对象、条件、用途或边界不同 | 分别保留并记录不合并理由 |

证据门槛先于共识判断。多个博主重复同一未核实数字、法律流程或平台机制，只能说明多人转述，不能变成可靠事实。多人共识表示来源层同向，不表示外部事实核实。

## 变化卡与人工审核

变化卡只在暂存版本中撤回该卡旧候选贡献，再重拆并重算受影响 atom。无法安全处理时保留上一成功版本贡献，不把失败的新哈希记入成功状态。

人工批准只改变候选分流或表述，不等于直接新增 atom。批准候选仍须与现有 atom 做语义比较：能合并先合并，确实是新命题才新增。

## 禁止静默删除

每个候选必须进入 atom、待人工判断或仅保留二层。任何没有处理去向的候选都使验证失败。
